# وِقاية — كاشف تعارض الأدوية لكبار السن

مشروع تجريبي (Prototype) بيعالج مشكلة: كبير السن بيروح لأكتر من دكتور، وكل دكتور
بيكتب روشتة من غير ما يشوف باقي الأدوية، فبيحصل تعارض دوائي خطير محدش واخد باله منه.

الأداة شغالة بالكامل جوه المتصفح (بدون سيرفر، بدون تسجيل بيانات)، وبتدعم العربي والإنجليزي.

---

## 1) هتشغليها إزاي (وإيه اللي هتنزليه على جهازك)

**الطريقة الأبسط:** افتحي ملف `index.html` بالدبل كليك — هيفتح في المتصفح (Chrome/Edge)
ويشتغل فورًا: البحث عن الأدوية، الإضافة، وفحص التعارضات كلها شغالة **أوفلاين بالكامل**.

**الحاجة الوحيدة اللي محتاجة إنترنت:** ميزة "صوّري الروشتة" (OCR) التجريبية، لأنها
بتحمّل مكتبة قراءة الصور (Tesseract.js) وملفات اللغة من الإنترنت أول مرة تستخدميها.
لو مفيش إنترنت وقتها، الميزة دي هتفشل برسالة واضحة — والإضافة اليدوية هتفضل شغالة عادي.

**مفيش أي تنصيب مطلوب** (لا Python ولا Node ولا حاجة) لتشغيل الاستخدام العادي.
لو حبيتي تجربة أستقر شوية (خصوصًا مع الـ OCR في بعض المتصفحات اللي بتمنع بعض العمليات
على ملفات `file://`)، ينفع تشغّلي سيرفر محلي بسيط (اختياري):

```bash
# لو عندك بايثون متثبت على جهازك:
cd المسار/بتاع/الفولدر/prescription-checker
python3 -m http.server 8000
# بعدين افتحي المتصفح على:
http://localhost:8000
```

لو مش عايزة تثبتي حاجة أصلًا، الدبل كليك على `index.html` كافي لـ 95% من الاستخدام.

---

## 2) محتويات الفولدر

| الملف | الوظيفة |
|---|---|
| `index.html` | الصفحة الرئيسية (إضافة أدوية، فحص تعارض، رفع صورة روشتة) |
| `eval.html` | صفحة **مقارنة الدقة** — OCR عادي مقابل التصحيح الذكي (للعرض في المسابقة) |
| `style.css` | التصميم (ألوان هادئة، خط كبير مناسب لكبار السن) |
| `db.js` | قاعدة بيانات الأدوية والتعارضات (نسخة JS تُحمَّل مباشرة بدون سيرفر) |
| `drugs_database.json` | نفس البيانات كملف JSON خام — دي اللي تستبدليها ببيانات DrugBank/RxNorm الحقيقية |
| `match.js` | **محرك المطابقة الذكية**: تطبيع النص + Levenshtein distance + البحث الضبابي |
| `app.js` | منطق الواجهة: الشرائح (chips)، فحص التعارض، ربط الـ OCR |
| `i18n.js` | قاموس الترجمة عربي/إنجليزي وتبديل اللغة |
| `eval.js` | كود اختبار الدقة الكمي (30 حالة اختبار محاكاة لأخطاء القراءة) |

## 3) إيه اللي اتعمل فعلًا، وإيه اللي "تجريبي/محاكاة" — بصراحة كاملة

عشان تقدري تعرضي المشروع في المسابقة بدون مبالغة، ده تفصيل دقيق:

### ✅ شغال فعليًا وبيتقاس رقميًا
- **محرك تصحيح ذكي حقيقي**: تطبيع نص عربي/إنجليزي (توحيد الألف والياء والتاء المربوطة،
  حذف التشكيل) + خوارزمية Levenshtein distance تقارن أي كلمة بكل الأسماء التجارية
  والعلمية في القاعدة وتطلع أقرب تطابق مع نسبة تشابه.
- **قاعدة تعارضات حقيقية سريريًا** (لكن عينة صغيرة يدوية وليست DrugBank الكاملة) —
  27 تفاعل موثّق طبيًا بين 23 دواء شائع عند كبار السن (قلب/سكر/ضغط/مفاصل)، بمستوى
  خطورة (خطير/متوسط/خفيف) ووصف مبسّط لكل حالة.
- **مقارنة كمية حقيقية** في `eval.html`: 30 حالة نص "مقروء بشكل ناقص" (محاكاة أخطاء
  OCR/خط اليد) بمقارنة استراتيجية "مطابقة تامة" (زي OCR عادي بدون تصحيح) ضد استراتيجية
  "المطابقة الضبابية". النتيجة الحالية على هذه العينة: **الدقة قفزت من ~23% إلى 100%**
  بعد إضافة التصحيح الذكي — رقم واضح تقدري تعرضيه للحكام.

### ⚠️ تجريبي / محاكاة — ولازم تقوليها بوضوح في العرض
- **الـ OCR الفعلي بيستخدم Tesseract.js** (محرك عام مفتوح المصدر)، **مش موديل مدرَّب
  خصيصًا على خط الأطباء** زي TrOCR المذكور في فكرتك الأصلية. تدريب موديل OCR مخصص
  يحتاج (أ) عشرات آلاف الصور الموسومة بخط أطباء حقيقي، و(ب) بيئة تدريب GPU، و(ج) وقت
  أطول من مدة المسابقة عادة. اللي تقدري تعمليه بدل التدريب الكامل: **fine-tuning خفيف**
  لموديل TrOCR جاهز على عينة صغيرة (حتى 50-100 صورة) باستخدام Google Colab المجاني —
  ده مشروع منفصل يحتاج بايثون، ومختلف تمامًا عن هذا التطبيق اللي شغال بالمتصفح.
- **قاعدة البيانات عينة يدوية صغيرة (23 دواء / 27 تفاعل)، مش DrugBank أو RxNorm الحقيقية.**
  DrugBank الحقيقي محتاج تسجيل أكاديمي/ترخيص وملفات ضخمة (XML بيتجاوز الجيجابايت) وربط
  عبر API يحتاج إنترنت مستمر — ده تقدري تضيفيه لاحقًا (شوفي قسم 5 تحت).
- **اختبار الدقة في `eval.html` اصطناعي (Synthetic)**: أنا كتبت أمثلة نصية تحاكي أخطاء
  قراءة شائعة، مش نصوص طالعة فعليًا من صور روشتات حقيقية. ده أسرع طريقة تثبتي بيها فكرة
  "التصحيح الذكي" بدون ما تحتاجي تصوير عشرات الروشتات، لكن **لازم تقوليها بوضوح للحكام**
  إن ده benchmark اصطناعي وليس على بيانات حقيقية.

## 4) لو عايزة ترفعي مستوى المشروع للمسابقة (خطوات مقترحة بترتيب الأولوية)

1. **صوّري 10-20 روشتة حقيقية** (بموافقة أهلك/معارفك، وبدون بيانات مريض حساسة) وجربي
   عليها الـ OCR الحالي، وسجّلي: كام كلمة اتقرت صح من غير تصحيح، وكام بعد التصحيح الذكي.
   ده هيدّيكي رقم حقيقي (مش اصطناعي) يقوّي عرضك جدًا.
2. **وسّعي قاعدة `drugs_database.json`** بمزيد من الأدوية والتعارضات — ينفع تنسخي بيانات
   من مصادر مفتوحة موثوقة زي NHS BNF أو WHO أو نسخة عامة من DrugBank Open Data.
3. **لو الوقت يسمح**: جربي fine-tuning لموديل TrOCR الجاهز (Hugging Face:
   `microsoft/trocr-base-handwritten`) على عينة الصور اللي جمعتيها، وقارني دقته بدقة
   Tesseract.js — ده هيكون "الابتكار العلمي" اللي فكرتك الأصلية بتتكلم عنه، لكنه
   مشروع بايثون منفصل (يحتاج بيئة تدريب، مش متصفح).
4. **أضيفي قسم "من أين هذه البيانات؟"** في العرض التقديمي يوضح بالضبط حجم العينة الحالية
   ومصدرها، عشان الحكام يشوفوا إنك فاهمة حدود شغلك مش بس بتقدّمي نتيجة نهائية مثالية.

---

## 5) لو عايزة تربطي DrugBank أو RxNorm فعليًا (خطوات تقنية)

- **RxNorm** (مجاني، من US National Library of Medicine): فيه REST API عام بدون مفتاح
  API للبحث عن اسم دواء وتحويله لكود RxCUI، وربطه بجداول تفاعلات. يحتاج إنترنت وقت
  التشغيل، وتقدري تستبدلي دالة `findInteraction()` في `app.js` بنداء `fetch()` لـ API
  RxNorm بدل البحث في `db.js` المحلي.
- **DrugBank**: يحتاج تسجيل حساب أكاديمي (مجاني للأبحاث) والموافقة على شروط الاستخدام،
  وبياناته بتيجي كملف XML ضخم لازم يتحوّل لقاعدة بيانات (SQLite/Postgres) قبل الاستخدام
  — مش حاجة تتحمّل مباشرة جوه صفحة HTML، فمحتاجة سيرفر خلفي (Python/Node) لو هتستخدميه.

هذا التطبيق الحالي مصمم بحيث لو استبدلتي `db.js` بمصدر بيانات أكبر (حتى لو جاي من ملف
CSV محوّل)، باقي الكود (البحث، الفحص، الواجهة) هيفضل شغال زي ما هو تقريبًا من غير تعديل كبير.

## 6) تنويه مهم

محدودة. أي تنبيه يظهر لازم يترجع فيه لصيدلي أو طبيب قبل أي قرار يخص دواء حقيقي.
